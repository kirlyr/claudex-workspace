# Global working agreements

- Follow runtime policy, user instructions and applicable project instructions; identify the active root, branch and stack first. Read only relevant context; preserve user changes.
- Spec-first: inspect relevant context read-only for new/complex work; establish outcome, scope and acceptance criteria. Never invent business rules: clarify correctness-critical ambiguities before the affected implementation. Skip repeated brainstorming for complete requirements; execute clear small changes directly. Obtain focused plan approval for large/risky changes, respecting existing approved scope.
- Reuse the active project's PRD, plan and decisions when useful; do not generate documents for every task. Follow existing architecture, keep scope minimal and verify proportionally; report actual checks and untested areas.
- On takeover in fresh or resumed sessions, read the active repository's `.local/workflow/HANDOFF.md`; verify project identity, Git status, staged/unstaged diffs, relevant untracked files, source and test evidence against it. Old conversation context may be stale; preserve approved requirements/decisions and continue only pending work, clarifying correctness-critical uncertainty.
- Update that same handoff at significant implementation/verification milestones, material decisions/scope changes/blockers, planned agent switches and session end; record last agent, objective, spec references, completed/in-progress/pending work, changed files, actual checks/untested areas and next action. Keep it concise; never persist logs/secrets or update after every tool call.
- Create a missing handoff only for substantial work after confirming it is ignored and untracked; preserve existing content and reconcile legacy `sessions/HANDOFF.md` without deleting it. If interrupted or the checkpoint is stale/missing, reconstruct from Git/source and label uncertainty; never assume usage-limit shutdown saved progress or import another project's memory.
- Keep existing workflows/skills/hooks intact; no duplicate bootstrap. Do not read unnecessary secrets, run production/shared migrations, or perform destructive database operations, deployment, credential changes or provider side effects without explicit approval.
- Never commit/push unless requested or automatically reset/stash/clean/force-push. Suggest file-specific staging and descriptive conventional commit commands after relevant milestones. Communicate concise evidence and blockers in Indonesian.
